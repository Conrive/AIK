# АИК-Надзор — учебная конфигурация 1С:Предприятие 8.5

Учебный проект, демонстрирующий полный жизненный цикл документов 
в надзорном органе: от создания проекта до регистрации, 
исполнения и отчётности.

> **Дисклеймер:** 
> Проект создан в учебных целях на базе учебной версии 1С: Предприятие. 
> Не является копией государственной системы «АИК-Надзор», 
> не распространяется и не используется в реальной деятельности.
> Все совпадения случайны.
> В конфигурации содержится некоторое количество [LEGACY] элементов,
> их функционал был переделан и используется иначе оригинальной идеи.
> Некоторые модули программного кода конфигурации были созданы с использованием генеративных ИИ инструментов,
> архитектрурные решения, алгоритмизация, тестирование и исправление програмного кода было произведено руками автора.

## Назначение

Конфигурация автоматизирует учёт документов в надзорном органе и 
поддерживает следующие бизнес-процессы:

- Регистрация входящей и исходящей корреспонденции.
- Создание проектов документов и их согласование (подпись/возврат).
- Учёт обращений с контролем сроков рассмотрения.
- Связывание документов между собой (ответ на обращение, 
  перенаправление, приложения, прочие документы).
- Пересылка документов между сотрудниками с контролем ознакомления.
- Назначение ответственных исполнителей и контроль исполнения.
- Отчётность по обращениям и исполнительской дисциплине.

## Требования

- **Платформа:** 1С:Предприятие 8.5 (рекомендуется 8.5.1 и выше).
- **Режим работы:** управляемое приложение, тонкий клиент.
- **СУБД:** файловая система.

## Установка и запуск

1. Создайте новую информационную базу без конфигурации.
2. Откройте конфигуратор, загрузите конфигурацию из `*.cf` 
   (или из xml развертки).
3. Обновите конфигурацию базы данных (F7).
4. Запустите 1С:Предприятие.
5. Создайте пользователей ИБ и назначьте им роли (см. раздел «Роли»).
6. Создайте сотрудников в справочнике `Сотрудники` и привяжите их 
   к пользователям ИБ (реквизит `Пользователь`).
7. Заполните справочники `Подразделения`, `Контрагенты`, 
   `Нормы сроков` (регистр `НормативныеСроки`).

В качестве примера заполнения БД можно использовать выгрузку информационной базы по пути ..\АИК\DT\1Cv8.dt

## Руководство пользователя

### Регистрация бумажного документа

**Роль:** Канцелярия, Прокурор.

1. Меню **Регистрация → Зарегистрировать новый**.
2. Заполните реквизиты: тип документа, описание, дату регистрации, 
   корреспондента (для входящих) или адресата (для исходящих).
3. Прикрепите скан документа (справочник `Файлы`).
4. Нажмите **Записать**. Внешний номер генерируется автоматически 
   по правилу `{Тип}-{ПорядковыйНомер}-{ГГ}`.

### Создание и подпись проекта

**Роль:** Офицер (создание), Прокурор (подпись).

1. Меню **Регистрация → Создать проект**.
2. Заполните реквизиты. Укажите **подписанта** — должностное лицо, 
   которое будет подписывать документ.
3. Нажмите **Отправить на подпись**. Статус меняется на `На подписи`, 
   документ автоматически пересылается подписанту.
4. **Подписант** открывает документ из списка «Новые документы» 
   и нажимает **Подписать** или **Вернуть на доработку**.
5. После подписи документ получает статус `Готово к регистрации` 
   и появляется у канцелярии в разделе «Проекты на регистрации».
6. **Канцелярия** открывает документ и нажимает **Зарегистрировать** — 
   генерируется внешний номер, статус меняется на `Зарегистрировано`.

### Поиск документов

**Роль:** все.

1. Меню **Поиск**.
2. Настройте фильтры: поле, вид сравнения, значение. 
   Можно добавить несколько условий:
   - Для **разных полей** условия объединяются через **И**.
   - Для **одинаковых полей** — через **ИЛИ** 
     (например: тип = Входящий ИЛИ Исходящий).
3. Нажмите **Найти**. Результаты отображаются в отдельной форме.

### Пересылка и ознакомление

**Роль:** все.

1. Откройте документ, нажмите **Переслать**.
2. Выберите одного или нескольких сотрудников.
3. Документ появится у них в разделе **«Все новые документы»**.
4. Получатель открывает документ и нажимает **Ознакомлен**. 
   Документ исчезает из списка новых.

### Назначение ответственного исполнителя

**Роль:** Прокурор.

1. Откройте документ, нажмите **Назначить исполнителя**.
2. Добавьте одного или нескольких сотрудников, укажите срок 
   и комментарий.
3. Нажмите **Назначить**. Исполнители получают поручения.

### Отчёт об исполнении

**Роль:** ответственный исполнитель.

1. Откройте документ из списка «На исполнении».
2. В блоке **«Отчёт об исполнении»** введите текст отчёта.
3. Нажмите **Провести исполнение**. 
   - В регистре фиксируется флаг `Исполнено` и дата.
   - Если все ответственные отчитались, документ переходит 
     в статус `Исполнен`.

### Отчёты

**Роль:** все (с учётом прав).

1. **Отчёт по обращениям граждан.** 
   Учитывает сроки рассмотрения по типам результата 
   (30/7/3 дня), выявляет просроченные обращения.
2. **Отчёт по работе с поручениями.** 
   Показывает, кто сколько поручений исполнил в срок и/или просрочил.

Период отчёта задаётся в форме отчёта.

## Архитектура проекта

### Общая схема

### Принципы построения

1. **Разделение UI и бизнес-логики.** 
   Бизнес-логика вынесена в общие модули. 
   Формы вызывают серверные методы и отображают данные.

2. **Регистры вместо табличных частей.** 
   Связи, пересылки, назначения и исполнения реализованы через 
   регистры сведений. Это позволяет:
   - избежать конфликтов блокировок;
   - обеспечить двойную запись для связей;
   - строить отчёты без сложных соединений.

3. **Жизненный цикл через перечисление.** 
   Статусы документа — это перечисление `СтатусыДокументов`. 
   Переходы контролируются в модуле `МодульСтатусовДокумента`.

4. **Разграничение прав через роли + RLS.** 
   Роли определяют доступ к объектам, RLS — к конкретным записям.

5. **Поиск через динамический список с параметрами.** 
   Фильтры собираются в SQL-условие на сервере и передаются 
   в динамический список через параметр `&ДинамическиеУсловия`. 
   Используется белый список полей для защиты от SQL-инъекций.
   > На позднем этапе разработки был выявлен более выгодный способ поиска через журнал документов, однако было принято решение оставить текущую архитектуру.

### Ключевые объекты

#### Документ `УчетныйДокумент`

Основной объект учёта. Реквизиты: тип документа, внешний номер, дата регистрации,
описание, примечание, скан документа, исполнитель, подписант, дата подписания, адресат, 
результат обращения, статус документа, регистратор, дата исполнения обращения.

#### Регистр `НумерацияДокументов`

Измерения: `ТипДокумента`, `Год`. 
Ресурсы: `ПоследнийНомер`.
Хранит счётчики внешних номеров по паре `(ТипДокумента, Год)`. 
Генерация номера выполняется в модуле менеджера 
`Документы.УчетныйДокумент.СгенерироватьВнешнийНомер` 
с управляемой блокировкой.

#### Регистр `СвязанныеДокументы`

Измерения: `Документ1`, `Документ2`, `ТипСвязи`.
Реализует двойную запись связок: при создании связи 
между А и Б создаются две записи — (А, Б) и (Б, А). 

#### Регистр `СтатусыОзнакомления`

Измерения: `Документ`, `Пользователь`. 
Ресурсы: `ДатаПересылки`, `Отправитель`, `Ознакомлен`, `ДатаОзнакомления`. 
Используется для записи сведений о пересылках документов.

#### Регистр `ОтветственныеИсполнители`

Измерения: `Документ`, `Сотрудник`. 
Ресурсы: `ДатаНазначения`, `Назначил`, `СрокИсполнения`, `Комментарий`,
`Исполнено`, `ДатаИсполнения`. 
Используется для записи поручений.

## Ограничения учебной реализации

1. **ЭП не реализована.** Подпись — условная, через кнопки. 
   В реальной системе требуется интеграция с криптопровайдером.
2. **Нет интеграции с внешними системами** (СМЭВ, ГАСПС).
3. **Отчёты не учитывают связи.** Срок исполнения обращения 
   считается по дате результата, без учёта связанных документов 
   и реального исполнения обращения.
4. **Нет автоматических уведомлений** (почта, мессенджеры).
5. **Упрощённая модель ролей.** В реальности используется 
   более широкая иерархия доступа к документам.
